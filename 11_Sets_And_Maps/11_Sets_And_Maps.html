C++17 Sets and maps - remembering what you have seen

Lesson 11 | Theory, cheat sheet and 12 practice problems from arena.olimpiici.com (Group D)

1. set: each value once, in order

A set is a bag that keeps every value only once and always keeps them sorted. Add #include <set>:

set<int> s;
s.insert(5);
s.insert(1);
s.insert(5);                     // already there: nothing happens
s.insert(3);                     // s is {1, 3, 5}

cout << s.size() << '\n';        // 3
cout << s.count(3) << '\n';      // 1 - it is there
cout << s.count(4) << '\n';      // 0 - it is not
s.erase(3);                      // s is {1, 5}

The easiest use of all: how many different values are there? Insert them all and ask for the size. Unlike a counting array (lesson 06), the values may be huge or negative, and they can even be strings.

2. map: a box for any key

A map is like a counting array whose box numbers can be anything: big numbers, negative numbers, words. Each box number is called a key. Add #include <map>:

map<string, int> cnt;
string w;
while (cin >> w) cnt[w]++;           // count every word

cout << cnt["apple"] << '\n';        // how many times "apple" appeared

map<long long, int> c;               // keys up to 10^18 - no array could do this
c[1000000000000LL]++;

A key that has never been used starts with the value 0, so cnt[w]++ just works.

Even looking at cnt[w] creates the key w with value 0. To ask "is the key there?" without creating it, use cnt.count(w).

3. Walking through a set or a map

A range for visits the values of a set from the smallest to the largest:

for (int x : s) cout << x << ' ';          // 1 5

In a map, each element is a pair: the key in first, the value in second. The keys come in sorted order:

map<int, int> cnt;
// ... cnt[x]++ for every x ...

int best = 0, bestKey = 0;            // the commonest key
for (pair<int, int> p : cnt)
    if (p.second > best) {
        best = p.second;
        bestKey = p.first;
    }

Because the keys are sorted, ties go to the smallest key - which is what most statements ask for.

4. Is it there? Fast lookups

A set answers "have I seen this value?" quickly, whatever the values are. That turns many slow double loops into one loop.

Two numbers with sum S. For every number x, the partner it needs is S - x. Ask the set whether that partner has already been seen:

set<long long> seen;
int pairs = 0;
for (int i = 0; i < n; i++) {
    long long x = a[i];
    if (seen.count(S - x)) pairs++;
    seen.insert(x);
}

Meeting in the middle. If you must match "something from list A" with "something from list B", put everything from A into a set (or a map with counts). Then walk B and look each one up.

5. Array, set or map?

The values are... and you need... Use
small whole numbers (up to about a million)counts or marksan array: cnt[x]
huge, negative or wordsonly which ones appearedset
huge, negative or wordshow many times each appearedmap

An array is the fastest. A set or map is a little slower - each step costs about log n - but it works for any values and keeps them sorted.

7. 4 pitfalls that cost real marks

Checking with m[key] adds the key.if (m[x] > 0) creates x with value 0. The map grows, and m.size() becomes wrong. Use m.count(x).
A set forgets repeats.{5, 5, 5} becomes {5}. If you need to know how many times, use a map with counts.
Changing p in the loop does not change the map.for (pair<int, int> p : m) p.second = 0; changes a copy. Write m[p.first] = 0; instead.
Using a map where an array would do.For values up to a million, cnt[x] is several times faster than m[x]. With a lot of input, that can decide the time limit.

8. Complexity reference

OperationCost
insert, erase, count on a set of n valuesO(log n)
m[key], m.count(key) on a mapO(log n)
Walking a whole set or mapO(n)
The same jobs with an arrayO(1) each
